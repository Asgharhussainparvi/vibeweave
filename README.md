# VibeWeave

**Different tastes. One unforgettable plan.** A culturally intelligent group-planning agent designed for the Qloo Agentic Hackathon.

## Current implementation status

- Responsive group planner with an editable four-person demo group.
- Server-side `/api/plan` route with bounded input validation, request timeouts, and safe API error messages.
- Qloo entity resolution through `GET /search` and taste-driven place discovery through `GET /v2/insights` when a server-side key is configured.
- Explicit demo fixtures when in Demo mode or when Auto mode is used without a key. Fixture cards are labelled `DEMO DATA`; they are never presented as live Qloo output.
- Live mode reports empty/error responses rather than silently substituting fixture data.
- Traceable resolved seeds, candidate source labels, swap/reject action, and copyable plan summary.

**Verification note:** the smoke test below checks local app readiness, demo provenance, and invalid-input handling. The health endpoint only detects whether a server-side key is configured; it does not verify Qloo authentication. Keep a separate record of your own live request, production build, mobile test, and deployment results.

## Requirements

- Node.js 22.19.0 or newer, as required by the current official Qloo hackathon kit.
- npm
- An event-issued Qloo API key for live mode.

## Obtain Qloo access first

The hackathon credential is issued by the event organizers; it is not generated by this app. Follow the [official Qloo hackathon kit](https://github.com/qloo/qloo-hackathon-kit) and its API access instructions. Install Node.js 22.19.0 or newer, then run `npm install --global @qloo/qloo-harness` and `qloo setup --qloo` as described by the kit. Never share the credential in chat or commit it. Confirm the event-issued credential instructions specify which API origin your team is allowed to use.

## Run locally

```bash
npm install
cp .env.example .env.local
# Put your own event-issued key in .env.local; do not commit this file.
npm run dev
```

Open the local URL printed by Next.js (usually `http://localhost:3000`). In PowerShell, use `Copy-Item .env.example .env.local` instead of the Unix `cp` command shown above. Without a key, select `Demo data` or use `Auto`; demo fixtures are clearly labelled. To use live data, set `QLOO_API_KEY` in `.env.local` and use the host required by the credential instructions in `QLOO_API_BASE_URL` (the default is the Qloo hackathon host).

## Environment variables

| Variable | Purpose |
| --- | --- |
| `QLOO_API_KEY` | Server-only event credential; never expose it to client code. |
| `QLOO_API_BASE_URL` | API origin approved for the credential; defaults to `https://hackathon.api.qloo.com`. |

Do not use `NEXT_PUBLIC_` for secrets. Do not paste credentials into public issues, chat, screenshots, or source control.

## API flow

1. Browser sends member tastes and planning constraints to the same-origin `POST /api/plan` route.
2. Server validates request size/count and restricts entity types to an allowlist.
3. Server resolves a bounded list of seeds using `GET /search?query=...&types=urn:entity:...&take=12`.
4. Server passes the resolved entity IDs and requested destination to `GET /v2/insights` with `filter.type=urn:entity:place`, `signal.interests.entities`, `filter.location.query`, and `take`.
5. The response exposes resolved seed names and the actual returned candidate list. It does not invent affinity scores or claim every group member likes each result.

If live API access fails, the UI reports the error; it does not silently substitute demo data. Qloo API access, entity-type permissions, rate limits, and response compatibility still need to be verified with the assigned event key.

## Smoke test

Start the app in one terminal with `npm run dev`. In a second terminal, run `npm run test:smoke`. You can set `VIBEWEAVE_BASE_URL` if the app is running on another local URL. The test checks `/api/health`, a demo plan, and invalid-input rejection. It does not consume Qloo quota and does not verify live Qloo authentication.

The `/api/health` endpoint reports only whether a key appears configured. It never returns the key and deliberately reports `qlooAuthVerified: false`; only a successful authenticated Qloo request can verify the credential.

## Deployment

Deploy as a Next.js app on Vercel or another compatible host. Configure `QLOO_API_KEY` and, if needed, `QLOO_API_BASE_URL` as server-side environment variables in the host dashboard. Keep `.env.local` out of Git. Verify the public URL and live API call after deployment.
